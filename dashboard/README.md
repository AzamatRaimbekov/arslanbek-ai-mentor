# Кабинет наставника Arslanbek

React + TypeScript + Vite. Работает с существующими таблицами `students`, `prompts`, `summaries`, `admins` в Supabase.

Текущий кабинет размещён в [Railway](https://frontend-production-a08a.up.railway.app).
Открытая [страница установки для учеников](https://frontend-production-a08a.up.railway.app/install)
доступна без входа в кабинет. На ней находятся скачивание школьного пакета,
отдельные инструкции для Claude Code, Codex и локального MCP, первое сообщение,
проверка доставки и обновление. В разделе «Подключение» наставник может
скопировать эту ссылку. Страница `/install` загружается отдельно от кабинета
и не обращается к API с данными учеников.
Режим — сводки от скилла без внешнего серверного ИИ. В разделе «Подключение» доступен
готовый пакет с адресом школы. Папка помещается в `~/.claude/skills/`; хуки
подключаются при использовании скилла, без ручного запуска установщика.
Школьный архив передаёт данные по ранее оформленному договору: отдельного вопроса
нет. Сохранённое отключение сохраняется; при первом подключении участник
автоматически регистрируется на API.
Данные входа администратора хранятся
только в локальном `backend/.env.railway-login.txt`.

## Запуск

Нужен Node.js 22.12 или новее.

```bash
cd dashboard
npm ci
npm run dev
```

Откройте адрес из терминала. Пока `.env.local` не заполнен, показан экран подключения. Дашборд работает только с подключённой базой Supabase; демонстрационного режима нет.

Полный порядок боевого запуска и проверки скилла: [backend/PRODUCTION.md](../backend/PRODUCTION.md).

## Настоящие данные

1. Создайте проект Supabase или используйте существующий проект школы.
2. Выполните в Supabase SQL Editor миграции по порядку:
   - `../backend/supabase/migrations/0001_telemetry.sql` — если ещё не применена;
   - `../backend/supabase/migrations/0002_dashboard.sql` — статистика и права чтения;
   - `../backend/supabase/migrations/0003_reliable_telemetry.sql` — идемпотентная доставка и допуск к анализу;
   - `../backend/supabase/migrations/0004_team_analysis.sql` — снимки и история отчётов команды.
3. В Authentication → Users создайте и подтвердите пользователя с email и паролем. Самостоятельной регистрации в дашборде нет.
4. Добавьте этого пользователя в список администраторов (замените email):

```sql
insert into public.admins (user_id, email)
select id, email from auth.users where email = 'mentor@example.com'
on conflict (user_id) do nothing;
```

5. Скопируйте `.env.example` в `.env.local` и заполните публичные параметры проекта:

```dotenv
VITE_SUPABASE_URL=https://PROJECT.supabase.co
VITE_SUPABASE_ANON_KEY=PUBLIC_ANON_OR_PUBLISHABLE_KEY
```

`service_role` / secret ключ не используется браузером. Все `VITE_*` переменные попадают в браузер. Доступ к данным обеспечивает Supabase RLS и таблица администраторов; клиентская проверка `is_admin` только управляет интерфейсом. Серверная функция анализа хранит свои секреты отдельно в Supabase.

6. В `../skills/arslanbek-ai-mentor/telemetry.conf` задайте **тот же** URL и публичный ключ (`SUPABASE_URL`, `SUPABASE_ANON_KEY`). Передайте обновлённый конфиг ученикам и установите хуки по инструкции основного README.
7. Перезапустите `npm run dev` и войдите под аккаунтом администратора. Для публикации задайте переменные окружения **до** `npm run build`; готовый статический сайт находится в `dist`.

Если база подключена, но данных ещё нет, интерфейс показывает пустое состояние. Ошибки соединения и доступа не подменяются демонстрационными данными. `telemetry.conf` настроен на сервер школы в Railway; публичные шаблоны `.env.example` остаются пустыми.

## Что можно посмотреть

- Общие показатели, новые и активные ученики за 14 / 30 / 90 дней, промпты по дням UTC.
- Распределение по уровням 0–5; отсутствие оценки учитывается отдельно от нулевого уровня.
- Поиск по именам, email, имени компьютера и пользователю ОС; фильтры по группе, уровню и активности; сортировка и страницы.
- Карточка ученика: все переданные данные аккаунта и устройства, профиль наставника, история промптов, проектов, сессий и оценок. Полный текст отображается как текст, без исполнения HTML из промптов или профиля.
- Изменение отображаемого имени и группы. Поля телеметрии администратор через дашборд не перезаписывает.
- CSV всех учеников **текущей выборки**, а не только открытой страницы. UTF-8 с BOM, разделитель `;`, защита от формул в ячейках. Секрет устройства и его хеш не запрашиваются интерфейсом и не экспортируются.
- Обновление раз в минуту на открытой вкладке и кнопка ручного обновления.
- Сводки скилла: общая лента с именем участника, проектом, временем, итогом работы, трудностями и следующим шагом. Переход из сводки в карточку участника. Отдельный серверный ИИ не вызывается.

Общие карточки и графики считают данные всей школы. Фильтры таблицы применяются к таблице и её экспорту. «Активные» в общей карточке — за выбранный период, зелёная точка в таблице — за последние 7 дней. Средний уровень считается по последним оценкам всех оценённых учеников; `null` не превращается в 0.

Запись создаётся при **первой успешной передаче данных после согласия ученика**, а не в момент скачивания скилла. Одна запись соответствует устройству (`device_id`): один человек с двумя устройствами может присутствовать дважды. Установки без согласия или без отправленных событий, старые установки без телеметрии, а также данные, которые скилл не собирает, в кабинете отсутствуют. Точное время установки, ответы агента и исходный код проектов не собираются. `first_seen` — первая передача данных, `last_seen` — время последнего приёма на сервере.

## Проверки

```bash
npm run build
npm test
npx playwright install chromium
npm run test:e2e
```

Тесты базы выполняют миграции в настоящем PostgreSQL через PGlite и проверяют RLS для анонимного клиента, постороннего пользователя и администратора, доступные изменения, интервалы, уровни и статистику более 1000 записей. Браузерные тесты проверяют фильтры, пагинацию, редактирование, историю, CSV, мобильный экран и отсутствие ошибок JavaScript. Отдельный сценарий с подменёнными HTTP-ответами проверяет вход, роль администратора, пустую базу, ошибку соединения и выход. Для имеющегося Chromium можно задать `PLAYWRIGHT_CHROMIUM_EXECUTABLE`.

Проверки базы изолированы и не подключаются к рабочей школе. Браузерные проверки запускают серверы на портах 5179 (тестовый URL с подменой HTTP-ответов) и 5181 (отсутствующие настройки). Настройки рабочего `.env.local` не используются. Отдельная проверка опубликованного кабинета — `node tests/production-smoke.mjs`. Скрипты скилла проверяются командой `python3 -B -m unittest discover -s backend/tests -v` из корня репозитория.

Справочные документы: [Supabase Auth](https://supabase.com/docs/reference/javascript/auth-signinwithpassword), [сборка и публикация Vite](https://vite.dev/guide/static-deploy).
