# Структурированная сводка для кабинета

В обновлённой сводке дополнительно заполняй `learning_evidence` и `tool_usage`
по `references/observability.md`: историю подтверждений навыков и применение
инструментов. Без подтверждений передавай пустые списки.

Сводку создаёт агент в рабочей сессии. Кабинет отображает её отдельными блоками,
поэтому отправляй данные по схеме, а не Markdown внутри одного поля.
Проверенная машинная схема — `scripts/progress_report.py:SCHEMA`;
полный пример — `references/progress-example.json` (пример не является наблюдением).

После содержательной задачи или блокера передай:

- `version: 1`, `task` — текущая задача; `goal` — ожидаемый результат.
- `stage`: discovery / planning / building / checking / delivery. Это этап задачи,
  а не уровень человека; прохождение предыдущих этапов не предполагается автоматически.
- `status`: in_progress / blocked / completed. Completed только при проверенном результате.
- `directions`: 1–8 наблюдаемых направлений, например «Frontend», «Аналитика», «Тестирование».
- `learner_actions`, `agent_actions`: отдельные списки фактически выполненных действий.
- `result`: что получилось и что ещё не завершено.
- `skills`: название навыка, `status` (strength / developing / needs_support / unknown),
  конкретное `evidence` и полезное упражнение `next_action`. Статус unknown при недостатке
  наблюдений; не присваивай низкую оценку за отсутствие информации.
- `checks`: что проверяли, `status` passed / failed / not_run, подтверждение в `evidence`.
- `blockers`: конкретные препятствия; пустой список, если их не наблюдали.
- `next_steps`: 1–5 действий с `action`, проверяемым `done_when` и `owner` learner / mentor.
- `confidence`: low / medium / high — достаточность наблюдений; `limitations` — чего не видно.

Не выводи рабочую продуктивность из числа сообщений. Укажи, где наблюдения относятся
к одному эпизоду. Не превращай сводку в кадровое решение или диагноз человека.
Не включай секреты, содержание сторонних разговоров и личные сведения вне задачи.

Отчёт преподавателю должен показывать изменение в работе, а не пересказывать чат:
свяжи результат с целью задачи; укажи самостоятельное действие ученика,
помощь агента и подтверждение проверки. В `skills.evidence` опиши конкретный эпизод,
а в `next_action` — упражнение или действие, которое проверит развитие навыка.
Сравнивай с прежним наблюдением только если оно действительно доступно; без него
не выдумывай рост в процентах или динамику за неделю. При блокере объясни в `blockers`,
что мешает продолжить, и назначь следующий шаг ученику или наставнику.

Имена, email, телефоны и сведения об устройстве не нужны для оценки обучения.
Пиши «ученик», «клиент», «участник», сохраняя техническое содержание и наблюдения.
Автоматический анонимизатор очищает вложенные поля перед отправкой, но не заменяет
эту редактуру. Таблицу обратных замен в сводку не включай. `references/privacy.md`.

В MCP вызови `arslanbek_submit_progress` с `report`, `project`, `session` и `model`,
если название модели известно. `level` можно опустить; тогда общий уровень неизвестен.
Без MCP сохрани JSON во временный файл и выполни:

```bash
python3 <папка-скилла>/scripts/telemetry.py report --file <JSON> --project <проект> --session <сессия>
```

Сохранять JSON в репозитории сотрудника не требуется. После отправки проверь статус
доставки, не путай очередь с подтверждением сервера. Не отправляй историю задним числом.
