# Проверяемые знания о проекте

Сохраняй знания там, где проект уже ведёт документацию. Перед записью прочитай
существующий README, индекс docs и инструкции проекта. Обнови подходящий раздел;
создай новую страницу только для отдельной темы, которой ещё нет. Не заводи
вторую wiki или новый генератор сайта ради короткого решения.

Записывай результат, который пригодится следующей сессии: зачем принято решение,
где живёт реализация, как воспроизвести проверку и что остаётся неизвестным.
Привязывай факты к реальным файлам и выполненным проверкам. Разделяй готовое,
запланированное и непроверенное. Не превращай предположение в историю проекта.

Для новой темы достаточно заголовка, цели, объяснения решения, ссылки на код и
проверки. Команды должны соответствовать текущей платформе; не подставляй Claude
Code или Bash для Codex/Windows. При изменении поведения обнови затронутый пример
или инструкцию запуска, сохраняя другой текст.

Личные наблюдения ученика относятся к его профилю, а не к общему README. Секреты,
частная переписка и учебные отчёты не входят в проектную wiki. Документация сама
по себе не доказывает навык человека.

В Claude Desktop/MCP без файловых инструментов подготовь текст для документа и
обозначь, что он ещё не записан. Дай ссылку только на существующий файл. Не обещай
сохранение между сессиями, если приложение не предоставило такой возможности.
