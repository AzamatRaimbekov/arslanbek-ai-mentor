# Локальное обезличивание

`scripts/anonymizer.py` работает без сети и внешних моделей. Он заменяет известные
имена, контакты, адреса, даты рождения, идентификаторы, IP, ссылки, домашние пути
и поля идентификации на устойчивые обозначения вида `[EMAIL_a1b2c3d4e5f6_0001]`.
Одинаковое значение получает одинаковый шаблон при повторной отправке. Проекты
и сессии также получают локальные псевдонимы. Техническое содержание сводки,
наблюдения о навыках, результаты проверок и следующие действия сохраняются.

Это обратимое **обезличивание с псевдонимами**, а не необратимая анонимизация.
Распознавание использует известные данные аккаунта, типы полей, шаблоны и при
необходимости локальный словарь дополнительных сущностей. Оно не гарантирует
нахождение всех произвольных имён или личных сведений в свободном тексте.
Дополнительные имена, организации и адреса можно зарегистрировать локально
через `entities`: массив объектов `category` и `value`. Изображения, аудио,
двоичные вложения и содержимое всех файлов компьютера этот скрипт не обрабатывает.

## Отправка школе

`telemetry.py` очищает промпты, профиль, все строки вложенного отчёта и поля
идентификации перед сохранением в очередь и повторно перед HTTP-запросом.
Ожидающие отправки записи старых установок очищаются до отправки. Ошибка
локального хранилища блокирует передачу; открытый вариант не отправляется.
Случайный ID устройства и технические ID событий сохраняют связь и повторную
доставку. Секрет авторизации устройства передаётся только API школы для проверки
отправителя; он не входит в содержание отчёта или таблицу восстановимых данных.

Таблица замен: `<ARSLANBEK_STATE>/privacy/vault.json`; по умолчанию это
`~/.claude/.arslanbek/privacy/vault.json`. На POSIX файлы создаются с правами `600`,
папка — `700`. На Windows применяются права пользовательской папки ОС;
хранилище не является зашифрованным сейфом. Блокировка и атомарная запись защищают
от одновременных событий нескольких сессий. Таблица не включается в пакет и не
передаётся на API. При потере таблицы восстановить старые шаблоны невозможно.

Пароли, ключи и токены удаляются без возможности восстановления. Не сохраняй
таблицу замен в проекте, логах, облаке, содержимом промпта или отчёта. Не открывай
её через инструменты модели. Не добавляй восстановление как MCP-инструмент:
его результат снова оказался бы в контексте внешней модели.

Уже принятые сервером старые записи не изменяются этим локальным обновлением.

## Запрос и возврат ответа в отдельном клиенте

Локальный клиент может встроить преобразование до отправки запроса своей модели:

```python
anonymizer = Anonymizer(local_vault_path)
safe_request, context = anonymizer.prepare(original_request, entities=local_entities)
safe_response = send_to_model(safe_request)  # отправляется только safe_request
local_response = anonymizer.restore(safe_response, context)
show_to_user(local_response)  # локальный показ, без повторной отправки в модель
```

`context` содержит разрешённые для восстановления шаблоны только этого запроса.
Шаблоны другой сессии или неизвестные шаблоны не раскрываются. Возвращённые
строки обрабатываются одним проходом, без исполнения текста и вложенных подстановок.

Для локальной проверки разработчиком доступны команды (путь к Python выбирается
для текущей ОС):

```bash
python3 scripts/anonymizer.py prepare --input input.json --json --output safe.json --context request-context.json --vault local-vault.json
python3 scripts/anonymizer.py restore --input safe-response.json --json --output local-response.json --context request-context.json --vault local-vault.json
```

Для обычного текста убери `--json`. В API или модель передаётся только `safe.json`;
контекст и таблица остаются локальными. Результаты записываются в локальные файлы,
содержимое не печатается в stdout. Эти команды не являются дополнительным шагом
установки для ученика: отчётность школы использует обработку автоматически.

## Граница встроенного чата приложения

Обычный скилл не является прокси для всего трафика Claude Code, Codex или других
приложений. Очистка отчётности не удаляет сведения из сообщения, которое уже
отправлено встроенной модели приложения. Для такой защиты нужно встроить
`prepare → отправка → restore` на стороне клиента до сетевого запроса и после
ответа, включая файлы и результаты инструментов, которые клиент добавляет в контекст.
Не называй загрузку скилла включением такой защиты.
